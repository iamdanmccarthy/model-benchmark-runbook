Live Benchmark Runbook

0/10

We give Claude Haiku, Sonnet and Opus the same messy hiring-pipeline CSV, with fake candidates, duplicate rows and mixed date formats. We ask each model three questions about it, then score the answers against a key computed by code, with no judge involved. Running each model many times in fresh contexts shows which one is the cheapest that's still reliably right, and how often the cheaper ones slip.

Do you need the biggest model to do recruiting work?

Claude comes in three sizes. Bigger ones cost more and run slower. Today we find out whether the small, cheap one is good enough for a real recruiting task.

Haikusmallest, fastest, cheapest Sonnetthe middle one Opuslargest, slowest, most expensive Fablethe very top of the range. Not in today's test. Do you really need it to write an email?

What we will do

Build a small test live, then run it on all three models.

  1. Make up a hiring pipeline. 60 fake candidates. IDs only, no names. Claude Code writes the program that makes them.
  2. Work out the right answers. Code calculates them from the data. Nobody types them in.
  3. Ask each model three questions. How many candidates are there? Which source has the best offer rate? How many active candidates are stale, meaning stuck in a stage for over 14 days?
  4. Run it 10 times per model. 30 runs in all, about 90 seconds. Each run starts from a blank slate, so no run can learn from another.
  5. Score it. A plain match against the answer key. No AI grader, so no opinions.
  6. Do it twice. First on clean data, where every model should do fine. Then on messy data: duplicate rows, blank stages, dates in mixed formats, inconsistent spelling.

What we are looking for

The cheapest model that gets every question right every time. If Haiku does that, there is no reason to pay for Opus on this kind of work.

The run prints a table with the score, speed and cost per run for each model.

What it does not prove

  • Ten runs per model is a demo, not proof. Results vary from run to run.
  • Each run goes through Claude Code, which adds its own built-in instructions on top of ours. So the numbers describe the models as run through Claude Code, not the models on their own. All three get the same setup, so the comparison between them is still fair. We do it this way to keep the demo simple. For a real benchmark, call the API directly, so the models get only your prompt and nothing else.
  • It tests one kind of task: counting and filtering pipeline data. Writing and judgment tasks may come out differently.
  • All data is fake. No real candidates anywhere.

What you need

Claude Code installed and signed in, and Python 3. No API key.

How long

About 25 minutes of steps. The model run itself is about 90 seconds. Go to the Runbook tab to start.

    Claude Code and Python are installed. No API key needed.

    claude --version

    Fresh folder, nothing carried over. Stay in this Claude session from here on. Run commands with ! in front.
    Terminal
    mkdir ~/live-benchmark && cd ~/live-benchmark
claude
  3. 2Fake data4 min
    60 fake candidates, IDs only, seeded, date frozen. Check: wc -l data/pipeline.csv shows 61. Show it: ! head -15 data/pipeline.csv
    Paste into Claude Code
    Write gen_data.py in Python 3, standard library only. It creates data/pipeline.csv with 60 fake hiring-pipeline candidates. Columns: candidate_id (C-0001 style, no names), role, source, stage, status, applied_date, stage_entered_date. Use 6 stages (Applied, Recruiter Screen, Hiring Manager Screen, Onsite, Offer, Hired), 4 sources, and status Active, Rejected or Hired. Seed the random generator and freeze today's date at 2026-11-18 so the output is identical every run. Then run it.
  4. 3Answer key3 min
    Answers computed by code, never typed. Tie check keeps each answer unique.
    Paste into Claude Code
    Extend gen_data.py to also write data/answer_key.json, computed from the data and never hand-written. Questions: (1) total candidates, (2) which source has the highest offer rate, where offer rate is candidates at Offer or Hired divided by all candidates from that source, (3) how many Active candidates are stale, where stale means more than 14 days in stage. Assert there is no tie for question 2. Run it and show me the key.
  5. 4Prompt and scorer4 min
    Three questions, strict JSON back, exact-match scoring. No AI judge.
    Paste into Claude Code
    Write prompt.md. It tells the model to act as a recruiting analyst, treat today as 2026-11-18, defines Active, days in stage, offer rate and stale as in the answer key, asks the three questions, and requires a reply of JSON only in this exact shape: q1_total_candidates, q2_best_offer_rate_source, q3_stale_active_count. Put {{CSV}} at the end where the file contents go. Then write the scoring function: exact match for each question. No LLM judge.
  6. 5Runner5 min
    Headless claude -p, no tools, empty folder per run. Parallel, timeout, one retry.
    Paste into Claude Code
    Write run_benchmark.py, standard library only. Config lives in models.json: runs_per_model and a list of models (claude-haiku-5-5, claude-sonnet-5-5, claude-opus-5-5). For each model and run, call: claude -p --model <model> --tools "" --no-session-persistence --strict-mcp-config --setting-sources "" --output-format json. Send the prompt on stdin and run it from an empty temporary directory so no context carries over. Parse the JSON reply, score it against data/answer_key.json, and record seconds and total_cost_usd. Run calls in parallel with a --parallel flag (default 6) and a --runs flag. Use a 300-second timeout per call with one retry, and leave failed runs out of the averages. Print a table: model, average score out of 3, pass count per question, average seconds, average cost, errors. Save results/latest.json.

    ! python3 run_benchmark.py --runs 1 --parallel 3 Clean data. Compare with step 8 after it gets messy.
    Terminal
    ! python3 run_benchmark.py --runs 1 --parallel 3
  8. 7Make the data messy3 min
    Key stays from the clean rows. Before the prompt, save the clean file: ! cp data/pipeline.csv data/pipeline_clean.csv After: wc -l data/pipeline.csv shows 68. Show the mess: ! head -15 data/pipeline.csv
    Paste into Claude Code
    Make the CSV messy without changing the answer key. After computing the key from the clean rows, corrupt the file: add 4 exact duplicate rows, add 3 rows with a blank stage, write about a quarter of the dates as MM/DD/YYYY and some as "Nov 3, 2026", and vary source capitalization and trailing spaces. Use a separate random generator so the clean data stays identical. Then update prompt.md with rules: count each candidate once, ignore blank-stage rows, dates are month-first in several formats, treat source names case-insensitively. Rerun gen_data.py.

    Pick the cheapest model that is right every time. Rehearsal: Sonnet and Opus were perfect every time. Haiku missed one question in 2 of 10 runs on the last pass and none in 13 earlier runs. Cost per run was about $0.004, $0.04 and $0.08. Results vary, so say what the table shows. Ten runs per model is a demo, not proof. Headless Claude Code adds its own system prompt, so this is not a raw API test.
